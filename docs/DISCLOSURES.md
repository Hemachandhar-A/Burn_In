# Disclosures

Written by the Lead during the G7 check (Session 7a) on a clean clone of `develop` at 4c96659 and updated in Session 7b after
the fixes. Every row was re-checked against the code or the committed results; items fixed in 7b (the wide CSV layout at the
upload route, lot-id validation, the reversed ranked lists, the stale dashboard after an upload, the In-Progress Module A
message, the PDF methodology claim, the borderline wording) were removed, and the rest were renumbered. This is the list of
limitations a judge could notice, each with the honest one-line statement.

## What to say if asked

1. **"Why does Module B never say WATCH?"** Module B is calibrated against a single safety slope, so it answers PASS or REJECT; WATCH is Module A's tier (#1).
2. **"Does Module B work on real parts?"** It is validated only on the generator's measurement scale; data of a very different magnitude is out of distribution, so production needs per-parameter calibration on the customer's own history (#2).
3. **"Why is about one part in six flagged, and why is precision low?"** Module A ranks parts within their own lot, so some are always the most extreme; at REVIEW it trades 18.4% precision for 84.1% recall at a 24.3% flag rate, a review-load trade, not a defect rate (#3, #4).
4. **"Is a pooled cross-lot history used?"** Not in the running app: the pooling and the cross-lot Isolation Forest are implemented and tested but the live pipeline feeds them nothing, and the report says so (#7, #25).
5. **"What happens to the preloaded lots after a restart?"** They are in storage; the in-memory lot state is rebuilt only by the next checkpoint upload, and the quality-flag route answers 404 until then (#15).
