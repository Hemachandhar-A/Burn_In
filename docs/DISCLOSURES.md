# Disclosures

Written by the Lead during the G7 check (Session 7a) on a clean clone of `develop` at 4c96659 and updated in Session 7b after
the fixes. Every row was re-checked against the code or the committed results; items fixed in 7b (the wide CSV layout at the

message, the PDF methodology claim, the borderline wording) were removed, and the rest were renumbered. This is the list of
limitations a judge could notice, each with the honest one-line statement.

## What to say if asked

1. **"Why does Module B never say WATCH?"** Module B is calibrated against a single safety slope, so it answers PASS or REJECT; WATCH is Module A's tier (#1).
2. **"Does Module B work on real parts?"** It is validated only on the generator's measurement scale; data of a very different magnitude is out of distribution, so production needs per-parameter calibration on the customer's own history (#2).
3. **"Why is about one part in six flagged, and why is precision low?"** Module A ranks parts within their own lot, so some are always the most extreme; at REVIEW it trades 18.4% precision for 84.1% recall at a 24.3% flag rate, a review-load trade, not a defect rate (#3, #4).
4. **"Is a pooled cross-lot history used?"** Not in the running app: the pooling and the cross-lot Isolation Forest are implemented and tested but the live pipeline feeds them nothing, and the report says so (#7, #25).
   - **"Do the benchmark numbers describe the demo?"** Not exactly: the benchmark ran Module A with the Isolation Forest active on pooled earlier lots; the demo runs it without, so the demo can flag slightly fewer parts (#7).
5. **"What happens to the preloaded lots after a restart?"** They are in storage; the in-memory lot state is rebuilt only by the next checkpoint upload, and the quality-flag route answers 404 until then (#15).

## RESOLVED in demo-v1.2 (release candidate, 2026-10-03) - append-only; no item above is deleted or renumbered

This section records, for the merged state (guard + disposition status + units + measurements + scoring switch), which old items are resolved and which limitations remain. Items #27-#30 come from the fixes branch, #31-#33 from the evidence branch (renumbered at merge; the evidence branch had also used #27-#29).

**Resolved in demo-v1.2:**

- **Old #14 - no finalized sign-off state: resolved.** `disposition_status` is derived from the stored sign-offs (`identity/status.py`) and shown as a badge on Part Detail; a written rationale is now required (422 on empty), and the lock after two distinct REJECT sign-offs is tested. See #30 for the rulings where the spec is silent.
- **Old #18 (and the unit part of #19) - missing units: resolved.** Chart axes, z-score table headers, sentences and the PDF delta table carry the canonical unit with an automatic SI prefix. (Old #26 is a layout item, not a units item, and is unchanged.)
- **#29 - PDF "explanation not yet available": resolved.** The report reads the stored sentence from `PartExplanation`.
- **Old #2 - skipped golden-route test: resolved in part.** The Module B out-of-range guard declines an off-scale input (`forecast_unavailable=True`) instead of over-flagging, and `test_golden_lot_through_the_route_is_hold` is un-skipped. Module B still has no usable forecast on a very different scale.

**Limitations that remain (not resolved by this release):**

- The guard cannot catch a lot that is exactly 10x off-scale (#27), and Module B's safety slope is one absolute number per part number (#28).
- Module A's flag rate is nearly constant across prevalence, so its cost advantage over static limits breaks at low prevalence (#33, extends #3 and #4).
- Module A's anomaly model rests on Gaussian-style assumptions (robust z, MCD); heavy-tailed or multimodal lots are not tested.
- Module B's accuracy is only about 7% better than the "168h = 24h value" persistence baseline, and its intervals under-cover (#31).
- The benchmark configuration (Isolation Forest active) is not the live configuration (#32, #25).
- The scoring experiment (`module_a/scoring.py`, `docs/SCORING_EXPERIMENT_RESULT.md`) is a switch only: `detect(scoring=None)` is the default and nothing is wired into fusion, so shipped behaviour is unchanged.
